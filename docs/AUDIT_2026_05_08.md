# drama-tutor audit — 8 May 2026

> 🚨 URGENT: Two P0 risks were found. First, the repository contains an `auto-session` Supabase Edge Function that can issue the configured family user's access and refresh tokens to any caller if deployed. Second, the accessible Vercel project and deployment evidence points to `prose-craft-aid`, not the `drama-tutor` repo, and the accessible public app is still Component 2 Prose content rather than Component 1 Drama.

## Executive summary

The Mode D Duchess data path is the strongest part of the current `drama-tutor` project: source routes exist, the client queries the correct Mode D tables, Supabase RLS includes anon SELECT policies for the three client-queried Mode D tables, and the database contains 3 Duchess routes, 40 active MCQ stem options, and 5 active annotated essay paragraphs.

The wider app posture is more fragile. The audit plan describes the app as intentionally unauthenticated, but the source actually attempts to create an authenticated session through a public `auto-session` Edge Function before loading most student-facing content. Most non-Mode-D content tables have authenticated-only SELECT policies, so the main pages rely on that auto-session path working.

The highest operational concern is deployment identity. The accessible Vercel account only exposed a project called `prose-craft-aid-main`; its deployments clone `Dr-T-B/prose-craft-aid`, and the live HTML for that domain describes Component 2 Prose / Hard Times / Atonement. I could not verify `https://drama-tutor.vercel.app` through the Vercel connector, so I have not claimed full live UX verification.

## Findings by severity

### 🔴 P0 — fix before 13 May

1. Public `auto-session` token vending risk.

- Finding: `supabase/functions/auto-session/index.ts` can sign in the configured family account using server-side secrets and return access and refresh tokens to the caller. It allows `Access-Control-Allow-Origin: *` and has no caller authentication, shared secret, origin allowlist, CAPTCHA, rate limiting, or invite-token check in source.
- Evidence/location: `supabase/functions/auto-session/index.ts`; `src/hooks/useAuth.ts` calls this function automatically when no session exists.
- Remediation: Disable the function immediately if deployed. Replace with either true anon-read RLS for public study content, or a protected login flow. If a short-term bridge is unavoidable, require a server-side one-time secret or allowlisted origin and rotate the family password/refresh tokens after disabling exposure.

2. Production deployment identity appears wrong or unverified.

- Finding: The accessible Vercel project is `prose-craft-aid-main`, not `drama-tutor`; the latest deployment clones `Dr-T-B/prose-craft-aid`, and the public HTML identifies itself as Component 2 Prose. The requested production URL `drama-tutor.vercel.app` could not be verified through the connector.
- Evidence/location: Vercel project/deployment metadata and public HTML fetch.
- Remediation: Verify Vercel project/domain mapping manually. Link the `Dr-T-B/drama-tutor` repo to the intended Vercel project, assign `drama-tutor.vercel.app`, redeploy `main`, and smoke-test the exact student URL before relying on it for revision.

### 🟠 P1 — fix soon, ideally after Component 1 and before 1 June

1. Authentication model conflicts with the stated architecture.

- Finding: The audit context says the app is intentionally unauthenticated and relies on anon key over RLS. Source code instead auto-signs into a Supabase user, while most non-Mode-D content tables are authenticated-only. That creates a brittle hidden dependency: if auto-session fails, key revision pages lose data.
- Remediation: Choose one architecture. For a single-user public revision PWA, the cleanest approach is anon SELECT RLS for public content tables and no hidden auto-login. For private access, use proper Supabase Auth and protect the app intentionally.

2. Main student pages do not consistently distinguish empty data from auth/query failure.

- Finding: Quotes and Themes wait on `useAuth()` and pass `userId` into hooks. Their data queries are disabled when `userId` is null, and the UI can show empty filtered results rather than a precise authentication/data-path failure. Critics shows a generic error only.
- Remediation: Add explicit page-level states: `auth_failed`, `query_failed`, `zero_rows`, and `content_loaded`. Surface the failing table/hook in development.

3. Hard-coded exam date is stale in Critics view.

- Finding: `CriticsView.tsx` hard-codes `2026-05-11` and displays `11 May 2026`, while the audit context says Component 1 Drama is Wednesday 13 May 2026.
- Remediation: Centralise exam dates in one config file and update the displayed Component 1 date to 13 May 2026.

4. Vercel security headers are incomplete in source config.

- Finding: `vercel.json` contains SPA rewrites only. Platform HSTS appears on the accessible Vercel response, but there is no source-level CSP, frame protection, referrer policy, permissions policy, or content-type options header configuration.
- Remediation: Add explicit headers in `vercel.json`, starting with `Content-Security-Policy`, `X-Frame-Options` or `frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy`, and `Permissions-Policy`.

5. Vercel environment variable scope was not accessible.

- Finding: I could not verify whether production/preview/development environment variables are scoped correctly or whether service-role secrets are absent from Vite-prefixed variables.
- Remediation: Manually inspect Vercel Project Settings -> Environment Variables. Confirm no service-role, JWT, private key, or password is exposed with `VITE_` prefix.

### 🟡 P2 — tech debt and improvements

1. Mode D route configuration can drift from database state.

- Finding: `DuchessHubPage.tsx` hardcodes `ROUTE_CONFIG` for Route A/B/C while the database is also the source for route rows. This repeats the route-key drift pattern.
- Remediation: Move trainer/reveal path metadata into a typed local map generated from a single config file, or store path/status metadata in the database with validation.

2. `ModeDDuchessRouteTrainer.tsx` is oversized and loosely typed in one critical place.

- Finding: The component is 453 lines and contains `paragraph_slot: slot as any`.
- Remediation: Split into `RoundScreen`, `FeedbackPanel`, `CompletionSummary`, and `AOProfileBars`. Replace `as any` with a typed parser/guard for paragraph slots.

3. Generated Supabase types are not evident.

- Finding: The client casts database results manually in several hooks.
- Remediation: Generate Supabase types and type the client with `createClient<Database>()`.

4. Broad anon table grants exist, though RLS policies currently prevent anon writes.

- Finding: Information schema grants show broad anon privileges on multiple tables. The effective RLS policy summary found no anon write policies, but broad grants are still noisier than necessary.
- Remediation: Revoke unnecessary anon INSERT/UPDATE/DELETE/TRUNCATE grants and keep explicit anon SELECT grants only where required.

5. README and project documentation are stale.

- Finding: README says the v6 schema has 49 tables, while the live public schema contains substantially more tables. The Vercel project/deployment still carries `prose-craft-aid` identity.
- Remediation: Update README to reflect current Drama Tutor architecture, Mode D deployment, auto-session decision, and actual setup/deployment steps.

6. Mode D indexing can be improved.

- Finding: Mode D has useful route/round indexes, but `mode_d_route_bank` lacks a composite index aligned to the client route query: `ao_profile_lock`, `play_code`, and route ordering.
- Remediation: Add a non-urgent composite index after the exam window if route-bank growth is expected.

7. No CI/test evidence was found in this pass.

- Finding: `package.json` has build/typecheck scripts, but I did not verify GitHub Actions or automated checks.
- Remediation: Add a minimal CI workflow for install, typecheck, build, and a small RLS smoke test script.

## Appendix A — Commands and queries used

### Supabase read-only SQL

```sql
select schemaname, tablename, rowsecurity
from pg_tables
where schemaname='public'
order by tablename;

select schemaname, tablename, policyname, permissive, roles, cmd, qual, with_check
from pg_policies
where schemaname='public'
order by tablename, policyname;

select tablename, policyname, roles, cmd, qual, with_check
from pg_policies
where schemaname='public'
  and (tablename like 'mode_d%' or tablename in (
    'themes','quotes','critics','critic_interpretations','essay_plans',
    'acts_scenes','revision_cards','exam_questions','essay_builder_questions',
    'essay_path_options','essay_path_feedback','essay_skeletons'
  ))
order by tablename, policyname;

select 'mode_d_route_bank' as table_name, count(*)
from mode_d_route_bank
where ao_profile_lock='DUCHESS_SECTION_B_AO1_AO2_AO3_ONLY'
union all
select 'mode_d_duchess_mcq_stem_options', count(*)
from mode_d_duchess_mcq_stem_options
where ao_profile_lock='DUCHESS_SECTION_B_AO1_AO2_AO3_ONLY' and is_active=true
union all
select 'mode_d_annotated_essay_paragraphs', count(*)
from mode_d_annotated_essay_paragraphs
where route_key in (
  select route_key from mode_d_route_bank
  where ao_profile_lock='DUCHESS_SECTION_B_AO1_AO2_AO3_ONLY'
) and is_active=true;

select table_name, column_name, data_type, is_nullable
from information_schema.columns
where table_schema='public' and table_name like 'mode_d%'
order by table_name, ordinal_position;

select tc.table_name,kcu.column_name,ccu.table_name as foreign_table_name,ccu.column_name as foreign_column_name
from information_schema.table_constraints tc
join information_schema.key_column_usage kcu
  on tc.constraint_name=kcu.constraint_name and tc.table_schema=kcu.table_schema
join information_schema.constraint_column_usage ccu
  on ccu.constraint_name=tc.constraint_name and ccu.table_schema=tc.table_schema
where tc.constraint_type='FOREIGN KEY'
  and tc.table_schema='public'
  and tc.table_name like 'mode_d%'
order by tc.table_name,kcu.column_name;

select schemaname,tablename,indexname,indexdef
from pg_indexes
where schemaname='public' and tablename like 'mode_d%'
order by tablename,indexname;

with p as (
  select tablename,
         bool_or(cmd='SELECT' and 'anon'=any(roles)) as anon_select,
         bool_or(cmd in ('INSERT','UPDATE','DELETE','ALL') and 'anon'=any(roles)) as anon_write_policy,
         bool_or(cmd='SELECT' and 'authenticated'=any(roles)) as auth_select
  from pg_policies
  where schemaname='public'
  group by tablename
)
select t.tablename, t.rowsecurity,
       coalesce(p.anon_select,false) as anon_select_policy,
       coalesce(p.auth_select,false) as auth_select_policy,
       coalesce(p.anon_write_policy,false) as anon_write_policy
```
